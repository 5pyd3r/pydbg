# Debugger 只做调试原语的门面

**Status**: accepted (2026-11-10)

`Debugger` 有 61 个公开方法、1,194 行，其中约 400 行是 handle 解析、事件循环与断点恢复的真实逻辑——与它自己的「组合门面」描述不符。我们决定：门面只承载**必须知道被调试进程**的东西——生命周期、事件循环，以及内存/线程/断点/模块原语；窗口探测、符号、hook、单步追踪、反汇编/汇编这些已经能独立构造并独立测试的能力，不再在门面上开入口。进程生命周期升为 `ProcessManager`。

**Considered Options**: 保持平铺（拒绝：那 400 行逻辑已经证明只会继续增长）；完全去掉门面（拒绝：交互式脚本需要一层顺手的入口）。

**Consequences**: 脚本写 `dbg.windows.probe(...)` 而不是 `dbg.window_probe(...)`；公开方法从 61 降到约 35。收益是门面不能再悄悄长胖——一个新能力必须先有独立模块和独立测试，才被允许存在。
