# 可回答性：拒绝不能伪装成答案

**Status**: accepted (2026-11-10)

库反复出现同一类静默失效：INT3 被目标覆写后断点再无动静、目标空闲被当成目标在跑、`read_memory` 丢弃已读部分、零命中的探测与「没查成」共用同一个返回值。它们各自都被事后补丁过（`verify_breakpoints`、`max_idle_timeouts`、`gaps`、F19 的零命中语义），但从未被写成一条规则。

我们决定把「可回答性」定为跨动态/静态的统一契约：**查询型 API 的返回必须能区分「答案」「带原因的拒绝」「空答案」；操作型失败一律抛 `PydbgError` 子类**。v0.2 只落实到最常用的 6 个查询，不追求一次性改造全库。

**Consequences**: 部分 API 会从「返回 None / 空列表 / 裸 int」变成带 `complete` 标志的结果对象，这是破坏性变更；调用方必须显式处理不完整的答案，而不能靠 `if not result` 蒙混过去。
